# TTS bake-off samples — Piper, Kokoro, Pocket TTS

Eight real outputs from a CPU bake-off of alternative TTS engines against VibeVoice, checked in
so anyone evaluating the shortlist can hear the difference without re-running inference. This is
the listening evidence for the engine choice; `samples/vibevoice/` holds the VibeVoice side.

Seven of the eight are the **same test passage** on every engine:

> Right, let's look at this together. When you factorise a quadratic, you're really asking: which
> two numbers multiply to give the constant term, and add to give the middle one? Let's try one.

The eighth (`ref_vibevoice_0.5b_carter_27s.wav`) is a **reference recording**, not the passage —
it is VibeVoice Realtime-0.5B output in the Carter preset, generated by us, and it is the source
audio two of the Pocket TTS clones were cloned from.

All files are mono 16-bit WAV.

## How they were generated

Run 2026-08-12 and 2026-08-18 on **CPU only** — 4-core Intel Xeon (Cascade Lake), 15 GB RAM, no
GPU — running Ubuntu 24.04 and Python 3.11.

## Measured throughput

Same passage, re-timed sequentially on an otherwise idle box. Figures are **×realtime, so higher
is faster** — the inverse of the RTF column in `samples/vibevoice/README.md`.

| Engine | ×realtime | Peak RSS | Clones? |
| :--- | :--- | ---: | :--- |
| Piper 1.6.0, `en_GB-cori-high` | 5.2x | 401 MB | No |
| Kokoro-82M (kokoro 0.9.4), `af_heart` | 3.1x | 1.6 GB | No |
| Pocket TTS 2.1.0 | 1.1-1.9x, 0.16-0.33 s to first audio, streaming | 1.0-1.5 GB | Yes |
| VibeVoice-1.5B (for scale) | 0.17x | 12.5 GB | Yes |

Two things keep these numbers honest:

- Cross-session speed on this sandbox varies by up to **~1.6x with identical code**, so treat this
  as one session's ranking, not absolute throughput.
- Pocket TTS pins torch to one thread on import, so its figure is **single-core**.

## Licensing — this corrects `docs/tts-engine-options.md`

That doc lists Piper as MIT. It is not, any more.

- **Piper** — code is **GPL-3.0-or-later since v1.3.0**, when the project moved from
  `rhasspy/piper` to `OHF-voice/piper1-gpl`. MIT describes v1.2.0 and earlier only. Voice models
  are licensed separately and vary: `en_GB-cori-high` (used here) is public domain, from LibriVox,
  but several popular `en_US` voices are **CC BY-NC-SA — non-commercial**. Check per voice.
- **Kokoro** — Apache-2.0 for both code and weights. No English voice carries a CC BY attribution
  requirement.
- **Pocket TTS (Kyutai)** — code MIT, but the **weights are CC-BY-4.0**, gated on Hugging Face
  behind a term prohibiting voice impersonation or cloning without explicit and lawful consent.

## Cloning findings

**Kokoro cannot clone.** The released checkpoint has no style or speaker encoder at all —
`KModel.forward` takes a style tensor, never audio. `kokoro_kokoclone_via_kanade.wav` was produced
by KokoClone, which synthesizes with a hardcoded preset voice and then runs a separate **Kanade
voice-conversion model** over the result. Kokoro is only the text front end there; the voice comes
from the converter. Treat "Kokoro cloning" in the options doc as a voice-conversion pipeline, not a
Kokoro feature.

**Piper cannot clone.** New voices require GPU finetuning from a transcribed corpus.

**Pocket TTS clones zero-shot, and it works.** `pocket_cloned_from_maya.wav` measured **0.912**
log-mel cosine similarity to its reference, against **0.817** for a preset voice and a ceiling of
0.995 (reference against itself). Median F0 landed within **1.7 Hz** of the reference.

**Four seconds of reference is enough.** Cloning the VibeVoice Realtime-0.5B Carter voice scored
**0.967 from a 4 s reference** vs **0.980 from the full 27 s** — statistically indistinguishable
(Welch p >= 0.22) — against a **0.931** no-clone floor. A longer reference buys run-to-run
consistency, not similarity: F0 standard deviation was 4.8 Hz at 27 s vs 8.0 Hz at 4 s. Embedding
costs about **1.1x the reference duration**, once, and exports a reusable **16.8 MB** preset that
reloads in roughly **1 ms**.

**Normalizing the reference does not improve the clone** — but output loudness tracks reference
loudness roughly 1:1, so normalize your reference if you want normal-level output.

## Caveats a listener needs

**These files are NOT level-matched.** Do not judge them by loudness. Against a -16 dBFS target:
Kokoro sits about **9.5 dB below** it; Piper is about **1.6 dB above** it and contains **3 clipped
samples**, because Piper peak-normalizes by default; the VibeVoice-derived files are quiet, roughly
**-22 to -26 dBFS**. Level-match before any A/B.

**Absolute similarity scores are not comparable between a real-human reference and a synthetic
one.** The whole scale compresses when both sides are machine speech, so the 0.912-vs-Maya and
0.967-vs-Carter numbers above cannot be ranked against each other.

**Pocket TTS reads reference WAVs as 16-bit PCM unconditionally.** A float32 reference raises, but
a **24-bit reference is silently misread as garbage** — no error, just a broken clone. Force 16-bit
on any reference recording you feed it.

**No engine tested has an en-ZA (South African English) voice.** Piper's catalogue is `en_GB` and
`en_US` only, and its bundled espeak-ng has no en-ZA phonemizer. Accent has to come from the cloned
reference.
