# Session report: free microdrama / TV-ad video on CPU

**Task (Ray, 2026-11-20):** Find out if Seedance 2.0 can run here; if not, find open video models that run on CPU (even slowly) and test them for microdramas (short serial drama episodes) and TV ads, so the media engine can do TV ads as well as radio ads. Build a no-Seedance dialogue test scene and report CPU time per finished minute.

**Status:** in progress (sandbox tests; no engine code committed yet).

## Findings so far
- **Seedance 2.0**: not open. Not on the ByteDance-Seed or ByteDance Hugging Face orgs. API only (BytePlus enterprise; resellers fal.ai / Replicate, about $0.30/s at 720p, $0.68/s at 1080p).
- **ByteDance open releases that matter**: LatentSync 1.6 (lip-sync onto video), Lynx and BindWeave (same face across clips, Wan 14B based), ContentV-8B (text-to-video), Bernini-R 1.3B (Wan 2.1 1.3B based), SeedVR2 (video upscaler).
- **Sandbox**: 4 CPU cores with AMX/bf16, 15 GB RAM, no GPU.
- **LTX-Video 2B distilled v0.9.8** (diffusers, bf16): 4 s 480x832 shot in about 6-7 min. Keeps an actor's face when a shot starts from a fixed actor photo. Weak at following direction. No sound.
- **Wan 2.2 TI2V 5B** (ComfyUI + GGUF Q8): 61 min for a 2 s shot even after enabling bf16 on CPU (ComfyUI forces fp32 on CPU by default; patched `should_use_bf16`, 2.3x faster). Too slow to be the shot maker.
- **VibeVoice 1.5B** (approved rev c00898d2, cfg 1.3): about 5-10 s CPU per 1 s of speech.
- **LatentSync 1.6 on CPU**: needs patches (CUDA hard-codes, CPU insightface detector, fp32 for grid_sample in affine_transform, bf16 UNet). About 16 min CPU per 1 s of video at 20 steps.
- **Dialogue test scene (12.9 s, 3 shots, 2 actors, lip-synced)**: voices 1.7 min + LTX shots 25 min + LatentSync 3 h 35 min = about 4 h CPU, so about 19 h CPU per finished minute (lip-sync is 89%). Faces stayed the same across shots because each shot starts from a fixed actor photo.
- Engine placement (from the one-audio-engine thread): shot making and episode assembly belong in rokct-media `video/` (protocol PR #612 has `rokct_media.video.vertical`), with voices/mixing via `rokct_media.compose` (protocol PR #611), not a new copy in factory.
- **Wan 2.2 S2V 14B** (ComfyUI, GGUF Q3_K_S + lightx2v 4-step LoRA, 6 steps, bf16 patch): photo + voice line -> 3 s talking clip at 320x544 in 59 min (~20 h CPU per finished minute). Lips, head and hands follow the speech; face stays the same.
- **Ovi (fp8, 12 GB)** runs on CPU after patches (SDPA instead of flash-attn, meta/mmap T5 load, fp8 Linear cast, fp32 VAEs): 5 s with its own voice in ~2 h 10 min (~25 h CPU per finished minute). Makes its own voice, so cast voices can't be reused.
- Model weak spots and shot rules are in the project's findings note.
- **Not runnable here**: HunyuanVideo-Avatar (13B, GGUF only as an experiment without a CPU runner) exceed the sandbox's 15 GB RAM and free disk.

## Decisions
- LTX-Video stays the CPU shot maker; Wan 5B ruled out on speed (decision_log.md).
- Session reports live in `.rokct/sessions/`, matching the other sessions' report PRs (#67, #69, #70). The current protocol end step keeps `.rokct/sessions/` (the factory copy of `end_protocol.py` is stale).
